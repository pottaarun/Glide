# Setup & configuration

How to run Glide locally, every configuration knob, and how to deploy. For how
the pieces fit together, see [Architecture](./architecture.md).

## Prerequisites

- **Node.js 20+** and npm (Vite 8 requires a current Node release).
- A **Cloudflare account** with **Workers AI** enabled.
- **[Wrangler](https://developers.cloudflare.com/workers/wrangler/)** — installed
  as a dev dependency, so `npx wrangler` / the npm scripts work out of the box.
- A **Cloudflare API token** — create one at
  [dash.cloudflare.com/profile/api-tokens](https://dash.cloudflare.com/profile/api-tokens).
- A **[Vectorize](https://developers.cloudflare.com/vectorize/) index** named
  `glide-guidance` for team-guidance RAG (create it once — see
  [The `VECTORIZE` binding](#the-vectorize-binding-team-guidance-rag)). Optional
  for local dev: without it, guidance falls back to injecting all enabled docs.
- _Optional:_ a running [Switchflare](https://developers.cloudflare.com/)
  migration-tool Worker for the provider-migration features.

## Quick start (local development)

```bash
# 1. Install dependencies
npm install

# 2. Configure local secrets
cp .dev.vars.example .dev.vars
#   then edit .dev.vars; set CF_API_TOKEN and/or GLIDE_TOKEN_KEY

# 3. Build the client bundle the Worker serves from ./dist/client
npm run build

# 4. Run the Worker locally (serves the SPA + the GlideAgent Durable Object)
npm run dev
```

Open the URL Wrangler prints, pick a display name, and you'll land in a fresh
room. Share the room URL with a teammate to collaborate.

For fast UI-only iteration, run the Vite dev server (no Worker/DO/AI):

```bash
npm run dev:ui
```

> **Tip:** You don't have to put a token in `.dev.vars`. If you set
> `GLIDE_TOKEN_KEY`, you can enter a Cloudflare API token directly into the GUI
> (**Connection → Set token**); it's stored encrypted in the Durable Object. See
> [Security model](./security.md). Never put a token in the chat composer.

## npm scripts

| Script | Command | What it does |
| --- | --- | --- |
| `npm run dev` | `wrangler dev` | Runs the full Worker (DO + AI + assets) locally. |
| `npm run dev:ui` | `vite` | Runs only the React UI dev server for quick iteration. |
| `npm run build` | `vite build` | Builds the client to `dist/client`. |
| `npm run deploy` | `npm run build && wrangler deploy` | Build, then deploy the Worker. |
| `npm test` | `node --experimental-strip-types --test tests/*.test.ts` | Run action-lifecycle, chat-integrity, and delivery/redaction regression tests. |
| `npm run types` | `wrangler types` | Regenerate binding types (`worker-configuration.d.ts`). |
| `npm run check` | `tsc --noEmit` | Type-check the project. |

> `worker-configuration.d.ts` is generated by `wrangler types` and is
> git-ignored. Run `npm run types` after changing bindings in `wrangler.jsonc`.
> Secrets are merged into `Cloudflare.Env` separately via `src/env.d.ts`.

## Configuration

### Non-secret vars (`wrangler.jsonc`)

| Var | Default | Purpose |
| --- | --- | --- |
| `GLIDE_MODEL` | `@cf/openai/gpt-oss-120b` | The Workers AI model that powers the chat brain. Full-precision, 128k context, reliable function calling. (gpt-oss is non-streaming on Workers AI; `workers-ai-provider` synthesizes the stream — see [Architecture](./architecture.md#the-chat-turn-lifecycle).) |
| `GLIDE_EMBED_MODEL` | `@cf/baai/bge-base-en-v1.5` | The Workers AI embedding model for **both** team-guidance and Cloudflare-docs RAG. Its output dimensionality (768) **must** match the `glide-guidance` Vectorize index. |

### Secrets / environment

Set these via `.dev.vars` locally or `wrangler secret put <NAME>` in production.
They're declared for TypeScript in `src/env.d.ts`.

| Name | Required | Purpose |
| --- | --- | --- |
| `CF_API_TOKEN` | Recommended | Cloudflare API token Glide uses to drive the API. Acts as the fallback when no GUI token is set. |
| `GLIDE_TOKEN_KEY` | Optional | Key used to derive the AES-256-GCM key that encrypts GUI-provided tokens at rest. **Without it, GUI token storage is disabled** and only `CF_API_TOKEN` is used. Generate one with e.g. `openssl rand -base64 32`. |
| `MIGRATION_API_URL` | Optional | Base URL of the Switchflare / migration tool Worker. Used as a fallback when the `MIGRATION` service binding isn't present. |

How a token is resolved at request time (`GlideAgent.getToken()` in `src/server.ts`):
**GUI-set token (decrypted) first, then `CF_API_TOKEN`.** If `GLIDE_TOKEN_KEY` is
missing or was rotated, Glide silently falls back to `CF_API_TOKEN`.

### The `VECTORIZE` binding (team-guidance RAG)

`wrangler.jsonc` declares a [Vectorize](https://developers.cloudflare.com/vectorize/)
binding for the team-guidance retrieval described in
[Architecture → Team guidance](./architecture.md#team-guidance-rag--srcguidance-ragts):

```jsonc
"vectorize": [{ "binding": "VECTORIZE", "index_name": "glide-guidance" }]
```

Create the index once, before your first deploy. Its dimensions and metric must
match `GLIDE_EMBED_MODEL` (`@cf/baai/bge-base-en-v1.5` → **768 dims**, cosine):

```bash
npx wrangler vectorize create glide-guidance --dimensions=768 --metric=cosine
```

> **Optional but recommended.** If the binding or index is absent, guidance still
> works: Glide falls back to injecting **all enabled** guidance docs into the
> prompt (every Vectorize/AI call is wrapped in try/catch and degrades quietly).
> RAG only kicks in once a room has more than `GUIDANCE_INJECT_ALL_MAX` (6)
> enabled docs, so small teams may never need the index. For local `wrangler dev`
> you can skip it entirely.

If you change `GLIDE_EMBED_MODEL` to a model with a different output size, delete
and recreate the index with matching `--dimensions`, then re-embed existing docs
from the admin dashboard (**Team guidance → Reindex**).

### Cloudflare-docs RAG & the weekly cron

The same `VECTORIZE` index also backs the **Cloudflare-docs RAG** (a shared
`__cfdocs__` namespace, separate from the per-room guidance keys). See
[Architecture → Cloudflare-docs RAG](./architecture.md#cloudflare-docs-rag--srcdocs-scraperts).

- **Populate it once** from the admin dashboard: open `/admin#<room>` → **Cloudflare
  docs** tab → **Start reindex** (the `startDocsReindex` RPC). It runs in the
  background and shows live progress.
- **It stays fresh automatically.** `wrangler.jsonc` declares a cron trigger,
  `"triggers": { "crons": ["0 2 * * SUN"] }`, so the Worker's `scheduled()` handler
  reruns the reindex every Sunday at 02:00 UTC. Cron triggers run only on deployed
  Workers, not under `wrangler dev`.
- **Optional.** Without the `VECTORIZE` binding the feature is inert — chat still
  works, it just won't cite the docs.

### The `MIGRATION` service binding

`wrangler.jsonc` can declare a service binding to a Worker named `switchflare`. It
is **commented out by default** so a fresh `wrangler deploy` succeeds without a
migration Worker in your account:

```jsonc
// "services": [{ "binding": "MIGRATION", "service": "switchflare" }]
```

Uncomment it to invoke the migration tool directly inside the runtime, which works
even when its public hostname is behind Cloudflare Access. It is **preferred** over
`MIGRATION_API_URL` (`src/migration.ts:108`).

> **Note:** If you uncomment this block but don't have a `switchflare` Worker
> deployed in your account, `wrangler deploy` will fail on the binding. Either
> deploy/point at your own migration Worker, leave the block commented out, or set
> `MIGRATION_API_URL` instead. With neither configured, the migration features are
> simply disabled and the tools explain how to enable them — the rest of Glide
> works.

For local development against a migration tool you run yourself, start it with
`wrangler dev` and point `MIGRATION_API_URL` at its origin (e.g.
`http://localhost:8788`).

### Cloudflare API token permissions

Reads and writes require matching token permissions. When an API call fails with
a permission error, Glide surfaces the exact permission to add — these come from
`PERMISSION_MAP` in `src/cf-api.ts:45`:

| API path contains | Permission to grant |
| --- | --- |
| `/dns_records` | DNS — Edit (Zone) |
| `/settings/` | Zone Settings — Edit (Zone) |
| `/rulesets` | Zone WAF — Edit (Zone) + Account Rulesets — Edit (Account) |
| `/rules/lists` | Account Filter Lists — Edit (Account) |
| `/load_balancers` | Load Balancers — Edit (Zone) |
| `/load_balancers/pools` | Load Balancing: Monitors and Pools — Edit (Account) |
| `/gateway/rules` | Zero Trust: Gateway — Edit (Account) |
| `/access/apps` | Access: Apps and Policies — Edit (Account) |
| `/cfd_tunnel` | Cloudflare Tunnel — Edit (Account) |
| `/teamnet/routes` | Cloudflare Tunnel: Routes — Edit (Account) |
| `/workers/scripts` | Workers Scripts — Edit (Account) |

Grant only what the team actually needs. `setCloudflareToken` first calls the
user-scoped `/user/tokens/verify` endpoint. Because that endpoint can return
401/403 for a valid account-scoped token, Glide then tries authenticated
`/accounts` and `/zones` reads. The token is marked unverified only when the
verify endpoint and both read fallbacks fail. A room that reconnects with a stored
unverified token calls `reverifyToken` once so old false negatives self-correct.

Verification proves authentication, not complete authorization. A green badge can
still be followed by a permission-specific failure when a later operation reaches
a product or scope the token cannot access.

## Deploying

```bash
# Create the guidance Vectorize index (once, recommended)
npx wrangler vectorize create glide-guidance --dimensions=768 --metric=cosine

# Set production secrets (once)
wrangler secret put CF_API_TOKEN
wrangler secret put GLIDE_TOKEN_KEY      # optional, enables GUI token storage
wrangler secret put MIGRATION_API_URL    # optional, if not using the service binding

# Build + deploy
npm run deploy
```

The Worker serves the built SPA from `./dist/client` via the `ASSETS` binding and
routes `/agents/*` to the `GlideAgent` Durable Object. `observability` is enabled
in `wrangler.jsonc`, so Worker logs/metrics are available in **Workers & Pages →
glide → Observability → Logs** and through `npx wrangler tail glide`.

A deploy can evict or restart the room Durable Object during an active turn. Avoid
deploying during live conversations when possible. After a deploy, wait for the
room's **live** badge or hard-refresh before sending another message.

### Deploy checklist

- [ ] `CF_API_TOKEN` set (or rely solely on GUI-provided tokens — but then set
      `GLIDE_TOKEN_KEY`).
- [ ] `GLIDE_TOKEN_KEY` set if you want teams to enter tokens in the GUI.
- [ ] `glide-guidance` Vectorize index created (768 dims, cosine) — or you accept
      guidance running in inject-all fallback mode.
- [ ] `MIGRATION` `services` block left commented out, **or** it points at a real
      Worker, **or** `MIGRATION_API_URL` is set, **or** you accept migration
      features being disabled.
- [ ] `npm run check` passes.
- [ ] `npm test` passes.
- [ ] Workers AI is enabled on the account and both `GLIDE_MODEL` and
      `GLIDE_EMBED_MODEL` are models you can access.
- [ ] _(Optional)_ Seed the Cloudflare-docs index after the first deploy from
      `/admin` → **Cloudflare docs** → **Start reindex** (the weekly cron keeps it
      fresh thereafter).

## Troubleshooting

- **The room says reconnecting:** keep the draft in the composer and wait for
  **live**. Hard-refresh if the socket does not recover after a deployment.
- **A message or response disappeared:** Glide checks `/get-messages` after an
  interrupted send. It restores an undelivered message to the composer or offers
  **Retry response** when the user turn persisted without an assistant reply.
- **A token stays unverified:** confirm that it can read at least one account or
  zone and that its resource scope includes the intended account. Replace it under
  **Connection → Change** if those reads fail.
- **The UI remains on "Loading room...":** use the full Worker URL from `npm run
  dev`; `npm run dev:ui` has no Durable Object backend. Also verify that the
  Worker has built assets and inspect the browser's WebSocket request.

For structured event meanings, log queries, and the incident workflow, see
[Troubleshooting & observability](./troubleshooting.md).
